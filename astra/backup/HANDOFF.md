# HANDOFF — astra-backup

Инструмент бэкапа исполняемых сборок Cesbo Astra и их выгрузки на FTP.
Путь: `D:\ClaudeCode\astra-backup`. Скрипты на bash (Linux / Git Bash).

## Разведка сайта (факты, на которых построены скрипты)

- URL сборки: `http://cesbo.com/and/astra-ГГММДД` (год-месяц-день, каждое поле 2 цифры).
- Существующая дата → `HTTP 200`, `Content-Type: application/octet-stream`,
  корректный `Content-Length`, есть `Last-Modified`/`ETag`, `Accept-Ranges: bytes`.
- Файл — 64-битный **Linux ELF** (~7–8 МБ), без расширения; имя = последний сегмент URL.
- Несуществующая дата → `HTTP 404`. Листинг каталога `/and/` → `403` (перебор дат обязателен).

## Архитектура

- `lib.sh` — дефолты + загрузка `config.env` (значения файла перекрывают дефолты),
  логирование, проверки. Требует bash ≥ 4 (ассоциативные массивы).
- `backup-astra.sh` — перебор дат `START_DATE..(--end|сегодня)`:
  есть файл → skip; известный старый 404 (кэш + окно `RECHECK_DAYS`) → skip; иначе проба,
  на 200 — атомарная загрузка. Кэш 404 — `state/missing.txt`.
- `upload-ftp.sh` — `curl --list-only` даёт имена на сервере; заливаются только
  отсутствующие; `--verify` сверяет размер. Креды — через временный curl-конфиг (chmod 600).
- `sync-all.sh` — backup + upload.

## Что протестировано (2026-09-13)

- Скачивание реального `astra-250325` — размер 7 952 192 совпал с `Content-Length`.
- Идемпотентность: повторный прогон ничего не качает, дублей нет, `*.part` не остаётся.
- Кэш 404: старые отсутствующие даты пропускаются без запроса; `--full` перепроверяет всё.
- `upload-ftp.sh`: `bash -n` чист; защита при пустом `FTP_HOST`; обнаружение локальных
  файлов, построение FTP-URL и обработка ошибки соединения — проверены на недоступном хосте.

## Что НЕ проверено вживую

- **Реальный round-trip на FTP** — нужен доступ к боевому серверу пользователя
  (логика/URL/передача кредов проверены, но заливка на живой сервер не гонялась).
- Полный прогон всего диапазона 2025→сегодня (первый прогон качает все имеющиеся сборки).

## Возможные доработки

- Атомарная заливка на FTP (upload в `*.uploading` + RNFR/RNTO) — сейчас `-T` пишет сразу
  в целевое имя; `--verify` закрывает случай битой прошлой заливки.
- Вариант выгрузки по SFTP/rsync (если FTP не подходит).
- Проверка контрольной суммы/подписи бинаря (сервер отдаёт `ETag`, можно сверять).

## Открытые вопросы к пользователю

- Где должен жить архив (эта Windows-машина `./archive` или каталог на Linux-сервере,
  напр. RAID)? От этого зависит `ARCHIVE_DIR` и где ставить cron.
- Реквизиты и адрес FTP для боевой выгрузки.
