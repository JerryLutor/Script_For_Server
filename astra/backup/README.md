# astra-backup

Резервное копирование исполняемых сборок **Cesbo Astra** с сайта разработчика и
выгрузка их на FTP. Инкрементально: качает и заливает только новое, дубликатов не создаёт.

Сборки лежат по адресу `http://cesbo.com/and/astra-ГГММДД`, где `ГГ`=год, `ММ`=месяц,
`ДД`=день (каждое поле ровно 2 цифры, напр. `astra-250325` = 25 марта 2025).
Листинга каталога у сервера нет, поэтому даты перебираются от `START_DATE` до сегодня;
существующая дата отдаёт файл (HTTP 200, ELF-бинарь ~7–8 МБ), отсутствующая — HTTP 404.

## Состав

| Файл | Назначение |
|------|-----------|
| `backup-astra.sh` | Скачивает новые сборки в локальный архив |
| `upload-ftp.sh`   | Заливает новые сборки из архива на FTP |
| `sync-all.sh`     | Сначала скачивание, потом выгрузка (для cron) |
| `lib.sh`          | Общие функции и загрузка конфигурации |
| `config.env`      | Настройки (отредактируйте под себя) |

## Требования

`bash >= 4`, `curl` (с поддержкой FTP), GNU `date`. Подходит Linux и Git Bash в Windows.
На macOS нужен свежий bash из brew (штатный 3.2 не годится).

## Быстрый старт

```bash
# 1) скачать всё доступное с 2025 года в ./archive
./backup-astra.sh

# 2) прописать FTP в config.env, затем выгрузить
./upload-ftp.sh
```

## Настройка (`config.env`)

```ini
START_DATE="2025-01-01"     # с какой даты качать (включительно)
# ARCHIVE_DIR="/mnt/raid5/astra-archive"   # где хранить архив (по умолчанию ./archive)
RECHECK_DAYS=45             # перепроверять «отсутствующие» даты за последние N дней
REQUEST_DELAY=0             # пауза между запросами, сек (0.2 — щадящий режим)

FTP_HOST="ftp.example.com"
FTP_PORT=21
FTP_USER="user"
FTP_PASS="secret"           # см. замечание о безопасности ниже
FTP_DIR="/astra"
FTP_TLS=0                   # 1 = FTPS explicit (AUTH TLS)
```

> **Безопасность:** пароль в `config.env` хранится открытым текстом — ограничьте доступ:
> `chmod 600 config.env`. Файл уже в `.gitignore`. При выгрузке пароль передаётся curl
> через временный конфиг (chmod 600), а не аргументом командной строки, чтобы не
> светиться в списке процессов.

## Как это остаётся актуальным (инкрементальность)

`backup-astra.sh` на каждом запуске:

- **файл уже есть** локально → пропуск без обращения к сети;
- дата ранее вернула **404 и старше `RECHECK_DAYS`** → пропуск (кэш `state/missing.txt`);
- остальные даты проверяются; при 200 файл качается **атомарно** (во временный `*.part`,
  затем `mv`), обрыв связи не оставляет битых файлов.

Так первый прогон обходит весь диапазон, а последующие делают лишь несколько запросов
(новые даты + окно перепроверки), не создавая дубликатов.

`upload-ftp.sh` берёт список файлов на сервере и заливает только отсутствующие там
(сравнение по имени). Флаг `--verify` дополнительно сверяет размер и перезаливает
недокачанные ранее файлы.

## Смена даты начала

Если поменять `START_DATE` (например, на более раннюю), **старые скачанные файлы не
удаляются** — архив только пополняется. Более ранняя дата просто до-качает то, чего ещё
нет; более поздняя — ничего не удалит.

## Опции командной строки

`backup-astra.sh`:

```
--start ГГГГ-ММ-ДД     начало диапазона (перекрывает config.env)
--end   ГГГГ-ММ-ДД     конец диапазона (по умолчанию — сегодня)
--archive ПУТЬ         каталог архива
--recheck-days N       окно перепроверки «отсутствующих» дат
--delay СЕК            пауза между запросами
--full                 игнорировать кэш и перепроверить весь диапазон
```

`upload-ftp.sh`:

```
--verify               сверять размер уже лежащих на сервере файлов, перезаливать битые
--archive ПУТЬ         каталог архива
```

## Автоматизация (cron, ежедневно в 03:30)

```cron
30 3 * * *  /path/to/astra-backup/sync-all.sh >> /var/log/astra-backup.log 2>&1
```

## FTPS / SFTP

- **FTPS explicit (AUTH TLS):** `FTP_TLS=1`.
- **FTPS implicit** (порт 990): поставьте `FTP_PORT=990` и в `upload-ftp.sh` схему `ftp://`
  замените на `ftps://` (curl тогда использует неявный TLS).
- **SFTP (SSH)** — другой протокол; если нужен именно он, выгрузку удобнее делать через
  `rsync -e ssh` или `sftp`; скажите — добавлю вариант.
